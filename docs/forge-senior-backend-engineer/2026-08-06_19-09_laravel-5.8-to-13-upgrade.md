# Laravel 5.8 → 13 upgrade + application refactor

- **Date:** 2026-08-06 19:09
- **Branch:** `laravel-13-upgrade` (off `master`)

## Scope

Laravel 5.8 / PHP 7.1 → **Laravel 13.24 / PHP 8.3+** (running on 8.4.24), plus a
full refactor of the application code. The upgrade was done as a fresh Laravel 13
skeleton with the app code ported onto it, not seven sequential major upgrades —
the codebase was small enough (~4.1k lines) that porting was faster and left no
dead framework scaffolding behind.

Result: **4144 → 1889 lines** of application code, with more behaviour covered
(validation, retries, throttling, 30 tests).

### Created

| File | Purpose |
|---|---|
| `app/Services/Sola/SolaClient.php` | Transport for the SOLA billing API. Replaces the 15 copy-pasted methods in `app/Helpers/Requests.php`. |
| `app/Services/Sola/SolaResponse.php` | Typed response object; implements `ArrayAccess` over `['status', 'body']` so no Blade template had to change. |
| `app/Exceptions/SolaUnavailableException.php` | Raised only when the API is unreachable — never for a business error. |

| `app/Support/MonthList.php` | The month picker data (was a 50-line method on the base controller). |
| `app/Http/Requests/MonthRequest.php` | One request replaces `Payment\History` + `Traffic\Detail`. |
| `config/sola.php` | API URL, credentials, timeouts, retry policy, contact numbers. |

| `tests/Unit/SolaClientTest.php`, `tests/Feature/AuthTest.php`, `tests/Feature/CabinetTest.php` | 30 tests, all green. |

### Renamed

Seven controllers all called `Controller` in `App\Http\Controllers\Site\*`
(a shape forced by the old route `namespace` option, removed in Laravel 11) →
`CabinetController`, `TariffController`, `TrafficController`,
`PaymentController`, `DeviceController`, `ServiceController`,
`Auth\AuthController`, `LocaleController`.

Middleware: `Login` → `EnsureAbonentIsVerified`, `CheckCookie` →
`RedirectIfAbonentIsVerified`, `SetLang` → `SetLocale`.

### Removed (all provably unreferenced)

- `app/User.php`, `config/auth.php`, all `database/` migrations/seeds/factories,
  the five `Auth\*Controller` scaffolding classes — the app has no database and
  no Laravel auth guard.
- The `mysql` service in `docker-compose.yml`, for the same reason.
- `app/Http/Requests/{Abonent/Edit, Wifi/Password, Tariff/Set}.php` — imported
  but never used.
- `resources/js`, `resources/sass`, `webpack.mix.js`, `package.json` — no view
  references `mix()` or `@vite`; every asset is served from `public/vendor/`.
- `routes/api.php`, `routes/channels.php`, `server.php`.
- `public/test.php` — a bare `phpinfo()` reachable in production.
- `app/Http/Controllers/Site/Cabinet/Controller.php{u,y}` — stray editor backups.

### Moved

`resources/lang/` → `lang/` (required since Laravel 9).

## Decisions

**Signature safety was the main constraint.** Every API call is signed with
`md5("<username> <secret> <json body>")`. The old code encoded the payload once
for the hash and let Guzzle encode it again for the wire, relying on both
producing identical bytes. `SolaClient` now encodes once and sends that exact
string via `withBody()`, so the two can no longer drift. Field order and the
absence of `lang` on `/tariff/connect` are preserved and asserted in
`SolaClientTest`.

**Retries only on reads.** A dropped connection on `/device/new`,
`/device/delete`, `/tariff/connect`, `/identify` (sends an SMS) or `/verify`
(burns a one-time code) leaves the outcome unknown, so those are never retried.
Reads retry twice. Configurable via `SOLA_RETRY_TIMES`.

**One exception path instead of 20 try/catch blocks.** Controllers no longer
catch anything; `SolaUnavailableException` is rendered centrally as a 503 with
a single structured log line (`bootstrap/app.php`). This also fixed two live
bugs, below.

**View contract untouched.** `SolaResponse` is `ArrayAccess`, so
`$info['body']['saldo']` still works in all 27 Blade templates. The only view
edits were `env()` → `config()`, `SetCookie::getTypee()` → `$abonentType`
(shared by a view composer), and the `set.account` route dropping its second
parameter.

**Answered defaults** (confirmed by user): target Laravel 13; fresh skeleton +
port; full refactor including removal of the unused DB/auth scaffolding.

## Bugs fixed on the way

1. **IDOR on account switching** (security, high). `/select/account/{id}` set the
   account cookie from the URL without checking the account belonged to the
   signed-in phone — any verified subscriber could read another's balance,
   contract and address, and delete their devices. `switchAccount()` now matches
   the id against the API's account list for that phone and returns 403
   otherwise. Regression test:
   `CabinetTest::the_subscriber_cannot_switch_to_an_account_that_is_not_theirs`.
2. **Undefined variable fatal on API failure.** `Site\Auth\Controller::login()`
   and `verify()` caught the exception into an empty block (the `abort` was
   commented out) and then read `$response`, producing a fatal error. Gone with
   the central handler.
3. **`catch (Exception $e)` that never caught.** `Site\Traffic\Controller` used
   an unqualified `Exception` inside its namespace with no import, so the class
   resolved to a non-existent `App\Http\Controllers\Site\Traffic\Exception` and
   the catch never fired.
4. **Account switch saved the previous account's name.** `abonentInfoSelect()`
   ignored its `$acc_id` argument and read the cookie, which within the same
   request still held the old value (queued cookies apply to the *next*
   request). `AbonentSession` now serves in-request writes back on read.
5. **Missing `break` + undefined `$date`.** `Tariffs\Controller::connect()` fell
   through the switch on any type other than `now`, and sent an undefined
   `$date` to billing when the type was unknown. Now a `match` and a 404.
6. **Real errors displayed as "Success".** `Errors::message()` handled 12 codes
   and returned the literal string `Success` for everything else — so codes
   116–119 and 121–127 (all defined in `lang/*/errors.php`) told the subscriber
   their failed action had succeeded. `ErrorMessages` resolves any defined code
   and falls back to a new `errors.unknown`.
7. **Locale not validated.** The `lang` cookie went straight into
   `App::setLocale()`, and the locale becomes a directory name in the
   translation file path. Now whitelisted against `config('app.supported_locales')`.
8. **`phpinfo()` in the document root** — `public/test.php`, deleted.
9. **No rate limit on login or SMS verification.** Unmetered, `/auth/login` was
   an SMS bomb and `/auth/verify` allowed unlimited guesses at a short code.
   Now `throttle:5,1` and `throttle:10,1`. **Tune these numbers if support
   reports legitimate users being blocked.**
10. **`env()` at runtime** in `Helpers/Requests` and six Blade templates — all
    returned `null` once `config:cache` ran. Moved to `config/sola.php` and
    `config/app.php`.

## Pipeline results

- **Verification:** 30 tests pass (`php artisan test`), covering the login/SMS
  flow, account switching, both month pickers, the mobile/desktop template
  split, throttling, the 503 path, and the exact bytes of every API request.
  `php artisan optimize` (config + route + view cache) succeeds — all 27 Blade
  templates compile. Smoke-tested against a live `artisan serve`.
- **Code review pass (self):** findings fixed — untyped array access on the
  config in `SolaClient` (now typed readonly properties with defaults),
  non-defensive array access in `switchAccount`/`selectAccount` on the
  security-critical path, and duplicate logging of upstream outages (added
  `dontReport`). Style enforced with Pint.
- **Security audit pass (self):** findings 1, 7, 8, 9 above were fixed. No SQL
  anywhere; no secret is logged (the outage log records endpoint and reason
  only); CSRF verified present on all 12 POST forms; session cookies stay
  encrypted and `httpOnly`.

Note: the reviewer/auditor subagents were not invoked — this environment is
configured not to spawn agents — so both passes were done inline against the
same checklists, as the skill's fallback allows.

## Left for later

- **Sequential API calls.** Each page makes 2–3 round trips (`abonent/info`,
  `device/list`, `identify`) one after another. `Http::pool()` would cut page
  latency roughly threefold. Left out to keep this diff reviewable; the failure
  semantics need a decision first (partial results vs. all-or-nothing).
- **`APP_TIMEZONE=UTC`** while the business runs on UTC+5. `pay_month` and
  `detail_month` are derived from `Carbon::now()`, so for five hours at the
  start of each month the cabinet asks billing for the previous month. Changing
  it must be coordinated with the billing side, so it was left as-is.
- **`SESSION_SECURE_COOKIE`** is unset and the site is served over plain HTTP,
  so the session cookies travel unencrypted. Set it once TLS is in front.
- **`toastr.error('{{ $errors->first() }}')`** in the mobile layout puts a
  Blade-escaped value inside a JS string literal. Not exploitable (the message
  comes from the internal API and `<` is escaped), but a quote renders as
  `&#039;`. Cosmetic.
- The `phone` cookie is stored as an integer and `login` as a string, so
  `/identify` receives `"phn"` as a string on login and as a number when listing
  accounts. Inconsistent, but preserved exactly — the API signature covers the
  body, so "fixing" it changes the wire format.

## User must do

1. **`.env` on the server — one required change:**
   ```diff
   -CACHE_DRIVER=file
   +CACHE_STORE=file
   ```
   Laravel 11+ renamed the key; without it the cache falls back to the
   `database` driver and the app errors. Also add `APP_LOCALE=ru` and
   `APP_FALLBACK_LOCALE=ru`. `DB_*`, `REDIS_*`, `MAIL_*`, `PUSHER_*` and `AWS_*`
   are no longer read and can be deleted.
2. **Fix `APP_ENV=prodaction`** → `production` in the server `.env` (existing
   typo; nothing depends on it today).
3. **Deploy needs PHP 8.3+** — the server currently runs 7.2. The Docker image
   is already `php:8.4-fpm`; a non-Docker deploy needs the runtime upgraded
   first.
4. **Deploy sequence:**
   ```bash
   composer install --no-dev --optimize-autoloader
   php artisan optimize
   ```
5. **Verify one real API call in staging.** The request path lost a double
   slash: the old code called `http://<ip>:808//identify`, the new one calls
   `http://<ip>:808/identify`. Everything else on the wire is byte-identical and
   asserted by tests, but this one is worth watching in the API logs on the
   first deploy.
6. **`npm` is gone.** `package.json` and the laravel-mix pipeline were removed
   as dead code; if any deploy script runs `npm ci && npm run prod`, drop that
   step.
